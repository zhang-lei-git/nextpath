# NextPath 可信数据生产线

## 目标

把分散的升学资料转化为可追溯、可审核、可发布、可被预测服务消费的数据。第一期只解决“生产可消费事实”，不追求覆盖所有学校或自动抓取所有平台。

家长端只读取已发布数据，并能看到数据年份、来源类型和更新时间。未核验的传言、单一博主观点和采集草稿不得进入预测或报告。

## 第一阶段范围

覆盖学校、招录参考和政策三类事实：

- 学校核心事实：办学性质、地址、食宿、管理与出口的有来源说明。
- 初中班型事实：学校原始班型名称、标准分类（创新/重点/平行/未知）、适用届别、选拔或分班规则及来源。
- 招录参考：地区、年度、学校、批次、招生计划、参考线、补录信息。
- 政策规则：地区、年度、规则名称、规则内容和适用范围。
- 每条事实绑定一个或多个证据，证据可以来自 URL、文件或人工记录。
- 事实先进入待审核状态，只有发布版本内的事实才可被消费。

第一阶段不做：全网自动爬虫、短视频自动下载、复杂专家评分、向家长开放的原始信息流、对主观评价给出确定性结论。

## 可验证需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| D1 | 记录来源和原始证据 | 每条候选事实可回到来源 URL、文件或人工说明，并保留采集时间。 |
| D2 | 结构化候选而非直接覆盖 | 新数据默认 `pending_review`，不能出现在消费查询中。 |
| D3 | 保留时间与口径 | 招录、政策、学校动态信息必须包含地区、年度和适用范围。 |
| D4 | 支持冲突处理 | 同一实体、字段、地区、年度的多个候选值可并存，审核时可选择发布值。 |
| D5 | 可审核发布 | 审核人发布一个数据版本后，版本内事实才成为对外可用数据。 |
| D6 | 可解释消费 | 消费 API 返回事实值、来源类型、发布日期和证据摘要。 |
| D7 | 可持续修正 | 修正创建新事实或新发布版本，不覆盖已发布历史。 |
| D8 | 数据缺口驱动采集 | 分析引擎可按地区、初中、班型、考试阶段创建缺口任务；工作台可按影响用户数和预测价值排序。 |
| D9 | 公开数据支持冷启动 | 用户样本不足时，已审核公开数据可作为分层先验，但必须保留来源、适用范围和可信等级。 |
| D10 | 用户结果形成校准样本 | 经授权、去标识化且审核通过的模考—中考配对数据进入模型候选集，不直接修改线上模型。 |
| D11 | 测试与回测隔离 | 测试、事后验证和生产预测数据具有独立用途标识；预测服务拒绝读取非生产预测数据。 |
| D12 | 未成年人数据可治理 | 保存监护人授权、用途、保留期限和撤回状态；支持删除原始个人数据并停止其进入后续训练。 |

## 角色与端

| 角色 | 主要端 | 第一阶段工作 |
| --- | --- | --- |
| 采集员 | 手机采集页 / PC | 上传文件、截图、粘贴链接、录入线索。 |
| 数据运营 | PC 数据工作台 | 标准化字段、合并重复、处理冲突。 |
| 审核人 | PC 数据工作台 | 查看原始证据、确认或驳回、发布版本。 |
| 家长 | 微信小程序 | 只读取与孩子相关的已发布结果。 |

PC 是生产和审核主端；手机只承担快速采集与简单待办。家长小程序不承担数据治理工作。

## 数据流

```text
来源登记 / 文件上传 / 链接采集 / 人工录入
                    ↓
                 证据 Evidence
                    ↓
              候选事实 Fact (待审核)
                    ↓
       标准化、交叉验证、冲突比对、人工审核
                    ↓
              发布版本 DataRelease
                    ↓
      预测服务、家长报告、学校与政策查询
                    ↓
             分析缺口 / 实际结果反馈
                    ↓
          定向采集、模型校准与新版本验证
```

## 数据约束

- 政策、分数线、一分一段、招生计划：必须有官方或主管部门来源才能发布为“确认”。
- 学校食宿、管理、出口：必须记录信息来源和采集日期；缺少充分证据时只发布为“参考观察”。
- 单一博主、家长或短视频：只能作为证据或线索，不能自动形成确认事实。
- 班型必须同时保留学校原始名称和标准分类；不得仅凭“实验班”等名称推断其层次，需记录适用届别和分班依据。
- 公开的排名去向、模考难度等非官方信息，只有在多来源交叉验证并人工审核后才可形成模型先验，且不能获得与配对真实样本相同的权重。
- 用户模考—中考结果必须去标识化、记录授权和数据届别，并与公开事实分库存储、分权限访问。
- 考试数据必须保存考试日期、类型、科目满分和计分方案；可获得时保存考试范围、参与范围、参考人数、试卷版本和发布主体。
- 每条事实的业务键为：`实体类型 + 实体名称/ID + 字段 + 地区 + 年度 + 适用范围`。
- 发布版本不可编辑；修正必须创建新的发布版本。

### 来源等级与模型用途

| 等级 | 典型来源 | 可发布用途 |
| --- | --- | --- |
| S1 | 教育局、考试院及正式政策原文 | 确认事实、政策约束、年度计分方案 |
| S2 | 学校官网、学校官方公众号、正式招生简章 | 学校事实、招生计划、班型和校区信息 |
| S3 | 多来源一致的媒体、机构或公开汇总 | 参考事实和冷启动先验，不得单独成为高置信结论 |
| S4 | 单一博主、家长口述、短视频 | 只作为采集线索，不能直接参与预测 |

公开信息成为模型先验时必须记录适用学校、班型、届别、考试阶段、有效期和最大允许影响。S3 先验不能缩小默认区间，也不能覆盖审核通过的纵向配对样本；超过有效期或出现冲突时自动降级并进入复核队列。

## 核心模型

```text
DataSource: 来源主体与可信等级
Evidence: 原始链接、文件、截图或人工记录
DataFact: 结构化候选事实，关联证据与审核状态
DataRelease: 一次可消费的数据快照
ReleaseItem: 发布版本包含的事实
DataGap: 分析引擎产生的定向补数任务
OutcomeSample: 去标识化的模考—中考纵向配对样本
ExamDefinition: 考试日期、范围、参与范围、满分、试卷版本和发布主体
ConsentRecord: 监护人授权、允许用途、授权时间、撤回时间和保留期限
```

`DataFact` 不代表真实世界的最终结论，只代表“有证据支撑、等待或已经通过审核的一条结构化主张”。

## 第一阶段接口

- `POST /data/sources`：登记来源。
- `POST /data/evidence`：登记证据。
- `POST /data/facts`：创建候选事实。
- `GET /data/facts?status=pending_review`：审核列表。
- `POST /data/releases`：将已审核事实发布为版本。
- `GET /data/consumer/schools/{name}`：读取已发布学校事实。
- `GET /data/consumer/admissions`：读取已发布招录参考。
- `GET /data/consumer/policies`：读取已发布政策。
- `POST /data/gaps`：登记或聚合分析缺口。
- `POST /data/outcomes`：提交经授权的中考结果候选样本。
- `POST /data/consents/{id}/revoke`：撤回数据授权并进入删除或停止训练流程。

第一阶段运营 API 需要独立管理员密钥，家长端不具备写入权限。正式后台接入多人账号、角色与审计权限后，再开放协作运营。

## 当前测试数据与运营台

`backend/scripts/import_legacy_volunteer_data.py` 将旧志愿预测系统的 `schools-data.js` 导入为 2026 年西安测试版本。导入学校档案、招生计划、一分一段参考点、公开预测区间和政策摘要，并保留来源、证据与可信度标识。该版本必须标记 `environment=test`、`data_purpose=demo_or_backtest`、`usable_for_prediction=false`；生产预测服务在仓储层和服务层都必须拒绝读取。脚本是幂等的：同名版本存在时不会重复导入。

PC 运营台使用独立的 5006 服务。浏览器先通过运营账号认证，服务端再携带管理员密钥调用私有 API；管理员密钥不会发送到浏览器。

## 演进

第二阶段已新增文件上传和网页采集任务：上传 TXT、CSV、JSON、DOCX、PDF 时保存原文件、创建 Evidence，并尽可能提取文本与治理提示；网页任务必须由运营人员配置来源与 URL，单次运行只生成 Evidence 与待治理材料。自动化不可绕过审核发布，也不会直接创建可消费事实。

采集模块目前作为模块化单体中的独立服务边界实现。进入持续采集后应独立部署为 collector-worker：读取同一份 CollectionJob 配置，按间隔执行、写入 DataIngestion/Evidence，运营台继续完成结构化、审核与发布。这样可以独立扩容、隔离外网抓取风险，并避免采集任务占用家长分析服务。

第三阶段基于历史发布版本、实际录取结果和人工纠错，更新来源评级与审核规则。规则和字段字典配置化、版本化，不将判断标准写死在模型代码中。

冷启动阶段优先补齐能直接改善消费结果的数据，不追求大而全。采集优先级为：年度政策与计分口径、招生计划与录取位置、初中和班型映射、同阶段模考—中考配对样本、学校管理等辅助信息。数据工作台按受影响用户数、目标学校热度、当前区间宽度和缺口严重度生成待办。

## 隐私与生命周期

- 学生成绩、排名、学校、班型和中考结果属于受限数据，只允许监护人本人及授权服务访问。
- 产品服务所需数据与模型训练授权分开；使用产品不默认同意训练。
- 撤回训练授权后，该样本不得进入新的训练集和模型版本；已发布模型保留版本审计，但不得恢复可识别个人信息。
- 用户申请删除后，在线个人数据应在 30 天内删除或不可逆匿名化；法律、安全审计和财务记录按明确期限单独保留。
- 原始截图、语音和上传文件只保留完成识别与确认所需的最短时间，默认不进入模型训练。
- 数据导出、删除、授权变更和运营访问必须写入不可篡改的审计日志。
