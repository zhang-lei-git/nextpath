# NextPath 可信数据生产线

## 目标

把分散的升学资料转化为可追溯、可审核、可发布、可被预测服务消费的数据。第一期只解决“生产可消费事实”，不追求覆盖所有学校或自动抓取所有平台。

家长端只读取已发布数据，并能看到数据年份、来源类型和更新时间。未核验的传言、单一博主观点和采集草稿不得进入预测或报告。

## 第一阶段范围

覆盖学校、招录参考和政策三类事实：

- 学校核心事实：办学性质、地址、食宿、管理与出口的有来源说明。
- 初中班型事实：学校原始班型名称、标准分类（创新/重点/平行/未知）、适用届别、选拔或分班规则及来源。
- 招录参考：地区、年度、学校、批次、招生计划、参考线、补录信息。
- 政策规则：地区、年度、规则名称、规则内容和适用范围。
- 每条事实绑定一个或多个证据，证据可以来自 URL、文件或人工记录。
- 事实先进入待审核状态，只有发布版本内的事实才可被消费。

第一阶段不做：全网自动爬虫、短视频自动下载、复杂专家评分、向家长开放的原始信息流、对主观评价给出确定性结论。

## 可验证需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| D1 | 记录来源和原始证据 | 每条候选事实可回到来源 URL、文件或人工说明，并保留采集时间。 |
| D2 | 结构化候选而非直接覆盖 | 新数据默认 `pending_review`，不能出现在消费查询中。 |
| D3 | 保留时间与口径 | 招录、政策、学校动态信息必须包含地区、年度和适用范围。 |
| D4 | 支持冲突处理 | 同一实体、字段、地区、年度的多个候选值可并存，审核时可选择发布值。 |
| D5 | 可审核发布 | 审核人发布一个数据版本后，版本内事实才成为对外可用数据。 |
| D6 | 可解释消费 | 消费 API 返回事实值、来源类型、发布日期和证据摘要。 |
| D7 | 可持续修正 | 修正创建新事实或新发布版本，不覆盖已发布历史。 |
| D8 | 数据缺口驱动采集 | 分析引擎可按地区、初中、班型、考试阶段创建缺口任务；工作台可按影响用户数和预测价值排序。 |
| D9 | 公开数据支持冷启动 | 用户样本不足时，已审核公开数据可作为分层先验，但必须保留来源、适用范围和可信等级。 |
| D10 | 用户结果形成校准样本 | 经授权、去标识化且审核通过的模考—中考配对数据进入模型候选集，不直接修改线上模型。 |
| D11 | 测试与回测隔离 | 测试、事后验证和生产预测数据具有独立用途标识；预测服务拒绝读取非生产预测数据。 |
| D12 | 未成年人数据可治理 | 保存监护人授权、用途、保留期限和撤回状态；支持删除原始个人数据并停止其进入后续训练。 |
| D13 | 定期自动采集 | 运营人员可配置采集来源、目标、频率、解析方式和启停状态；调度器按计划创建可重试的采集运行。 |
| D14 | 变化检测 | 相同内容不重复治理；网页正文、附件或结构发生变化时创建新证据并记录差异。 |
| D15 | 自动治理候选 | 系统自动提取、标准化、匹配实体、去重、识别冲突和异常，只写入候选库，不直接发布。 |
| D16 | 全流程日志 | 每次运行可查看采集、提取、治理、审核和发布的逐步日志、输入输出、耗时、版本和失败原因。 |
| D17 | 可重放与幂等 | 同一来源内容和规则版本重复执行不产生重复事实；失败步骤可从原始证据重新执行。 |
| D18 | 失败与新变化告警 | 连续失败、页面结构变化、重要政策更新和高价值冲突进入运营待办并产生告警。 |

## 角色与端

| 角色 | 主要端 | 第一阶段工作 |
| --- | --- | --- |
| 采集员 | 手机采集页 / PC | 上传文件、截图、粘贴链接、录入线索。 |
| 数据运营 | PC 数据工作台 | 标准化字段、合并重复、处理冲突。 |
| 审核人 | PC 数据工作台 | 查看原始证据、确认或驳回、发布版本。 |
| 家长 | 微信小程序 | 只读取与孩子相关的已发布结果。 |

PC 是生产和审核主端；手机只承担快速采集与简单待办。家长小程序不承担数据治理工作。

## 数据流

```text
定时调度 / 文件上传 / 链接采集 / 人工录入
                    ↓
           CollectionRun 采集运行
                    ↓
     原始快照、附件、哈希与 Evidence
                    ↓
       提取、实体匹配、标准化、去重
                    ↓
     冲突比对、异常检测、候选事实 Fact
                    ↓
                 人工审核
                    ↓
              发布版本 DataRelease
                    ↓
      预测服务、家长报告、学校与政策查询
                    ↓
       分析缺口驱动采集优先级和规则优化
```

自动化只允许把数据推进到候选事实和待审核状态。第一阶段所有正式发布都需要人工确认；后续即使对 S1 官方结构化来源开放自动发布，也必须通过来源白名单、字段白名单、规则版本、回滚和抽检机制单独审批。

## 定期采集设计

### 采集任务

每个 `CollectionJob` 至少配置：任务名称、来源、目标 URL 或入口、采集类型、适用地区、数据类型、调度表达式、超时、重试次数、限速、解析器、治理规则集、负责人、启停状态和优先级。

首期支持以下采集方式：

- 官方网站列表页与详情页；
- 学校官网和公开招生页面；
- 可直接访问的官方公众号文章链接；
- PDF、Word、Excel、CSV、JSON 和图片附件；
- 运营人员上传文件或粘贴链接；
- 无法稳定自动获取的来源生成定期人工采集待办。

首期不承诺绕过登录、验证码、平台访问限制或反爬措施。短视频和封闭平台内容只登记线索或由运营人员上传，不建设规避平台限制的采集器。

### 变化检测与快照

每次运行保存响应状态、最终 URL、采集时间、正文哈希、附件哈希、页面结构摘要和原始快照位置。系统按以下规则处理：

- 哈希和关键结构均未变化：记录 `unchanged`，不进入重复治理；
- 正文或附件变化：创建新证据，生成新旧差异并进入治理；
- 页面不存在或跳转异常：标记 `source_changed`，等待运营确认；
- 同一文件在不同来源出现：保留多个来源关系，底层文件只保存一份；
- 来源撤回内容：不删除历史证据，创建撤回事件并通知审核人评估已发布数据。

### 自动治理

治理流水线按规则版本执行：

1. 提取正文、表格、附件和图片文字；
2. 判断资料类型、地区、年度、届别、批次和适用范围；
3. 匹配学校、校区、班型和政策实体，保留原始名称与标准 ID；
4. 将分数、位次、人数、日期、计划和科目满分转换为标准字段；
5. 按业务键查重并比较已发布值、现有候选值和本次提取值；
6. 根据来源等级、交叉证据、时间有效性和异常规则形成可信度建议；
7. 产生候选事实、冲突项、异常项和需要人工补充的字段。

结构化解析器优先处理表格和明确字段。大模型只用于非结构化资料的分类、抽取、实体候选和摘要，输出必须通过字段类型、枚举、范围和业务规则校验；提示词、模型和抽取模板均需版本化。

### 状态机

采集运行使用统一状态：

```text
scheduled -> running -> captured -> extracted -> normalized -> pending_review
                |           |            |              |
                v           v            v              v
              failed      failed      conflict       approved/rejected
                                           |              |
                                           v              v
                                      pending_review   published
```

长期无法解析、疑似恶意文件或不符合来源规则的内容进入 `quarantined`。`failed`、`conflict` 和 `quarantined` 都必须形成可处理待办，不能静默结束。

## 日志与可追溯性

日志分为三层：

- 任务日志：调度时间、开始结束时间、状态、耗时、重试、抓取数量和错误摘要；
- 数据项日志：来源 URL、响应、快照、哈希、提取结果、差异、候选事实和冲突；
- 治理审计：解析器版本、规则版本、大模型与提示词版本、人工修改、审核意见、发布版本和回滚记录。

运营人员必须能够从任一发布事实反查到候选事实、治理步骤、原始证据和采集运行；也能从任一失败运行重新执行采集、提取或治理步骤。日志和证据不可因任务重跑被覆盖。

## 数据工作台页面

PC 端按消费优先级建设以下页面：

1. 数据总览：新数据、待审核、冲突、失败、过期数据和采集覆盖率；
2. 采集任务：新增、编辑、启停、立即运行、调度和负责人；
3. 运行日志：逐步状态、耗时、输入输出、错误和重试；
4. 变化对比：网页或文件的新旧差异及受影响事实；
5. 治理队列：实体匹配、字段标准化、重复合并和异常修正；
6. 审核发布：原始证据、候选值、冲突值、审核意见和发布版本；
7. 数据缺口：按受影响用户数、目标学校热度和预测区间宽度排序；
8. 质量监控：来源成功率、数据新鲜度、自动提取通过率、冲突率和人工修改率。

## 数据约束

- 政策、分数线、一分一段、招生计划：必须有官方或主管部门来源才能发布为“确认”。
- 学校食宿、管理、出口：必须记录信息来源和采集日期；缺少充分证据时只发布为“参考观察”。
- 单一博主、家长或短视频：只能作为证据或线索，不能自动形成确认事实。
- 班型必须同时保留学校原始名称和标准分类；不得仅凭“实验班”等名称推断其层次，需记录适用届别和分班依据。
- 公开的排名去向、模考难度等非官方信息，只有在多来源交叉验证并人工审核后才可形成模型先验，且不能获得与配对真实样本相同的权重。
- 用户模考—中考结果必须去标识化、记录授权和数据届别，并与公开事实分库存储、分权限访问。
- 考试数据必须保存考试日期、类型、科目满分和计分方案；可获得时保存考试范围、参与范围、参考人数、试卷版本和发布主体。
- 每条事实的业务键为：`实体类型 + 实体名称/ID + 字段 + 地区 + 年度 + 适用范围`。
- 发布版本不可编辑；修正必须创建新的发布版本。

### 来源等级与模型用途

| 等级 | 典型来源 | 可发布用途 |
| --- | --- | --- |
| S1 | 教育局、考试院及正式政策原文 | 确认事实、政策约束、年度计分方案 |
| S2 | 学校官网、学校官方公众号、正式招生简章 | 学校事实、招生计划、班型和校区信息 |
| S3 | 多来源一致的媒体、机构或公开汇总 | 参考事实和冷启动先验，不得单独成为高置信结论 |
| S4 | 单一博主、家长口述、短视频 | 只作为采集线索，不能直接参与预测 |

公开信息成为模型先验时必须记录适用学校、班型、届别、考试阶段、有效期和最大允许影响。S3 先验不能缩小默认区间，也不能覆盖审核通过的纵向配对样本；超过有效期或出现冲突时自动降级并进入复核队列。

## 核心模型

```text
DataSource: 来源主体与可信等级
Evidence: 原始链接、文件、截图或人工记录
CollectionJob: 调度、采集目标、解析器和治理规则配置
CollectionRun: 一次采集运行及其状态、指标和错误
SourceSnapshot: 原始响应、正文/附件哈希、快照位置和差异
ProcessingStep: 提取、治理和审核步骤的输入输出日志
GovernanceRuleVersion: 字段字典、实体映射、校验和冲突规则版本
DataFact: 结构化候选事实，关联证据与审核状态
DataRelease: 一次可消费的数据快照
ReleaseItem: 发布版本包含的事实
DataGap: 分析引擎产生的定向补数任务
OutcomeSample: 去标识化的模考—中考纵向配对样本
ExamDefinition: 考试日期、范围、参与范围、满分、试卷版本和发布主体
ConsentRecord: 监护人授权、允许用途、授权时间、撤回时间和保留期限
OperationAlert: 连续失败、来源变化、重要更新和高价值冲突待办
```

`DataFact` 不代表真实世界的最终结论，只代表“有证据支撑、等待或已经通过审核的一条结构化主张”。

## 核心接口

- `POST /data/sources`：登记来源。
- `POST /data/collection-jobs`：创建定期采集任务。
- `PATCH /data/collection-jobs/{id}`：调整调度、解析器、规则和启停状态。
- `POST /data/collection-jobs/{id}/run`：立即创建一次采集运行。
- `GET /data/collection-runs`：按任务、状态和时间查询运行日志。
- `GET /data/collection-runs/{id}`：查看逐步日志、快照、差异和错误。
- `POST /data/collection-runs/{id}/retry`：从失败步骤安全重试。
- `POST /data/collection-runs/{id}/reprocess`：用新解析器或治理规则从原始证据重新处理。
- `GET /data/governance-rules`：查看字段、实体匹配、校验和冲突规则版本。
- `POST /data/governance-rules`：创建新的治理规则版本，旧运行继续保留原版本。
- `GET /data/alerts`：查看连续失败、来源变化、重要更新和高价值冲突。
- `PATCH /data/alerts/{id}`：处理或重新打开运营待办。
- `POST /data/evidence`：登记证据。
- `POST /data/facts`：创建候选事实。
- `GET /data/facts?status=pending_review`：审核列表。
- `POST /data/facts/{id}/review`：审核候选事实并记录修改与意见。
- `POST /data/releases`：将已审核事实发布为版本。
- `GET /data/consumer/schools/{name}`：读取已发布学校事实。
- `GET /data/consumer/admissions`：读取已发布招录参考。
- `GET /data/consumer/policies`：读取已发布政策。
- `POST /data/gaps`：登记或聚合分析缺口。
- `POST /data/outcomes`：提交经授权的中考结果候选样本。
- `POST /data/consents/{id}/revoke`：撤回数据授权并进入删除或停止训练流程。

第一阶段运营 API 需要独立管理员密钥，家长端不具备写入权限。正式后台接入多人账号、角色与审计权限后，再开放协作运营。

## 采集与治理验收

使用一个官方列表页、一个详情页、一个 PDF 附件和一个人工上传表格完成以下验收：

1. 调度器按配置产生运行，立即运行和定时运行不能重复处理同一内容；
2. 首次采集保存原始快照并产生候选事实，第二次无变化只记录 `unchanged`；
3. 修改测试页面或附件后能生成差异并只治理受影响内容；
4. 同一学校别名能够匹配标准实体，无法确定时进入人工队列；
5. 冲突值不能自动覆盖已发布数据，必须经审核形成新发布版本；
6. 断网、超时、解析失败和恶意文件能够重试或隔离，并保留完整日志；
7. 任一发布事实可以反查到来源、快照、处理步骤、人工修改和发布版本；
8. 测试、回测和未发布候选数据不能被生产预测 API 读取。

## 当前测试数据与运营台

`backend/scripts/import_legacy_volunteer_data.py` 将旧志愿预测系统的 `schools-data.js` 导入为 2026 年西安测试版本。导入学校档案、招生计划、一分一段参考点、公开预测区间和政策摘要，并保留来源、证据与可信度标识。该版本必须标记 `environment=test`、`data_purpose=demo_or_backtest`、`usable_for_prediction=false`；生产预测服务在仓储层和服务层都必须拒绝读取。脚本是幂等的：同名版本存在时不会重复导入。

PC 运营台使用独立的 5006 服务。浏览器先通过运营账号认证，服务端再携带管理员密钥调用私有 API；管理员密钥不会发送到浏览器。

## 演进

当前基线已支持文件上传、定时网页采集、立即运行、暂停、失败重试和原始快照重新治理。系统保存网页及附件快照、内容哈希、正文差异和逐步日志；治理规则按版本维护，可完成字段别名、实体别名、允许数据类别、自动候选去重和同对象同年度同字段冲突识别。冲突只进入运营待办和候选审核，不会覆盖已审核或已发布数据。

采集调度器已经独立运行；下一步将采集执行与治理处理进一步拆成 collector-worker 和 governance-worker，并补齐数据缺口优先级、连续失败/结构异常告警、事实全链路追溯和质量指标。各 worker 读取同一份任务、快照和步骤日志，可独立扩容和限流，采集失败不得占用家长分析服务资源。

第三阶段基于历史发布版本、实际录取结果和人工纠错，更新来源评级与审核规则。规则和字段字典配置化、版本化，不将判断标准写死在模型代码中。

冷启动阶段优先补齐能直接改善消费结果的数据，不追求大而全。采集优先级为：年度政策与计分口径、招生计划与录取位置、初中和班型映射、同阶段模考—中考配对样本、学校管理等辅助信息。数据工作台按受影响用户数、目标学校热度、当前区间宽度和缺口严重度生成待办。

## 隐私与生命周期

- 学生成绩、排名、学校、班型和中考结果属于受限数据，只允许监护人本人及授权服务访问。
- 产品服务所需数据与模型训练授权分开；使用产品不默认同意训练。
- 撤回训练授权后，该样本不得进入新的训练集和模型版本；已发布模型保留版本审计，但不得恢复可识别个人信息。
- 用户申请删除后，在线个人数据应在 30 天内删除或不可逆匿名化；法律、安全审计和财务记录按明确期限单独保留。
- 原始截图、语音和上传文件只保留完成识别与确认所需的最短时间，默认不进入模型训练。
- 数据导出、删除、授权变更和运营访问必须写入不可篡改的审计日志。
