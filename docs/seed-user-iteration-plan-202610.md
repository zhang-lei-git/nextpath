# 种子用户版本迭代计划

## 目标

让 5–10 个真实家庭可以不依赖人工指导完成：建立档案、选择初中和目标高中、录入或上传一次成绩、查看当前升学范围、查看中考情景预测、回看报告，并在第二次成绩后看到变化。

## P0：种子用户开始前必须完成

### 1. 身份与数据隔离

- 线上使用微信身份令牌；生产环境关闭内部测试身份回退。
- 新用户进入时只能看到自己的空档案。
- 增加跨用户读取档案、成绩和报告的接口测试。
- 微信登录失败时给出可理解的重新进入提示，不展示技术错误。

验收：两个微信用户分别建立档案后，任何接口都不能互相读取数据。

### 2. 成绩录入闭环

- 手工录入总分或各科成绩均可保存。
- 各科成绩存在时总分自动计算，体育缺省 60 分。
- 支持成绩修改并重新生成分析和报告。
- 图片上传失败、格式错误、超过大小和网络失败均能回退到手工录入。
- 图片识别结果必须进入家长确认环节，不能直接写入成绩。

验收：新用户连续录入两次成绩，首页、成绩列表、分析页和报告使用同一份最新数据。

### 3. OCR 接入

- 接入阿里云通用文字识别。
- 首版识别考试名称、日期、科目成绩、总分、班级排名、年级排名和年级人数。
- OCR 失败时保留图片并生成可编辑的待确认记录。
- 识别结果与科目总分不一致时提示家长核对。
- AccessKey 仅从 ECS 环境变量读取，不进入小程序和 Git。

验收：使用 5 种不同排版的脱敏成绩单，识别后均能进入确认页；识别失败也能完成手工保存。

### 4. 分析结果核查

- 验证仅总分、总分加年级排名、多次模考、无目标和有目标五类输入。
- 每个情景的预测分数段和位次段来自同一结果。
- 数据不足时降低结论精度，只展示学校层次，不伪造具体学校。
- 页面和报告不展示模型、参数、权重或治理过程。

验收：固定测试数据的预测结果满足分数越高、位次越靠前；正常发挥、发挥较好、成绩有波动三种情景均可解释。

### 5. 基础数据消费核查

- 初中和高中搜索能返回主要学校。
- 目标学校没有边界数据时清楚提示数据不足。
- 计分方案按届别读取，不能按考试日历年份误判。
- 中考前分析不读取出分后的一分一段表和录取结果。

验收：用种子用户常见学校和目标高中逐一搜索，并能打开学校详情或得到清晰的缺失提示。

### 6. 真机回归

完整走通：首次进入 → 建档 → 搜索学校 → 设置目标 → 录入成绩 → 查看首页 → 查看分析 → 查看报告 → 修改成绩 → 再次查看变化。

## P1：种子用户使用一周后完成

- 优化首页和报告中的家长文案。
- 完善趋势图的满分变化、缺失排名和特殊考试展示。
- 增加运营台按用户查看档案、成绩、分析、报告和错误的排查视图。
- 记录分析耗时、接口错误、OCR 失败和用户退出位置。
- 根据真实家庭反馈调整位次范围宽度和学校层次表达。

## P2：种子验证后再做

- 异步分析任务和失败重试。
- 会员、支付和权益限制。
- 多城市扩展。
- 完整志愿组合优化。
- 大规模自动采集和复杂知识点分析。

## 发布门槛

- 后端自动测试全部通过。
- 至少 5 个真实家庭完成第一次录入。
- 至少 3 个家庭完成第二次录入。
- 没有跨用户数据访问问题。
- 没有阻断式图片上传问题。
- 家长能说清楚孩子当前大致学校范围和下一步关注点。
