# NextPath 开发计划

## 目标与原则

本轮开发先建立可信数据生产线，再替换分析模型，最后更新家长端。任何阶段未通过验收，不进入依赖它的下一阶段。

统一原则：

- 自动采集和治理只产生候选事实，未经审核不得进入生产预测；
- 测试、回测和生产数据隔离，先解决数据污染风险；
- 分数和位次联合预测，不能单独修正其中一个结果；
- 小程序只展示家长关心的结论，内部过程只在运营端和回测中出现；
- 每阶段独立提交、测试和部署，保留回滚能力。

## 里程碑一：可信数据底座

### 阶段 1：数据结构与兼容迁移

开发内容：

- 学生档案增加学校原始班型和标准班型；
- 考试增加考试范围、参与范围、参考人数和试卷版本；
- 数据发布增加环境、用途、可用于预测、有效期和数据截止字段；
- 新增采集运行、原始快照、处理步骤、治理规则版本、数据缺口、纵向结果样本、授权和运营告警模型；
- 分析运行增加考试时间、运行时间、数据截止时间、状态和多模型版本快照；
- 引入可回滚数据库迁移，保留旧成绩、报告和发布数据。

验收：旧数据可读取，迁移可重复执行和回滚，现有小程序不因字段升级立即中断。

### 阶段 2：数据边界与生产隔离

开发内容：

- 预测仓储统一校验 `environment=production`、`usable_for_prediction=true` 和发布时间；
- 当年已发布政策和计划可以使用，当届出分结果、一分一段和录取结果只能进入回测；
- 当前硬编码的 2026 测试曲线和学校预估线退出生产路径；
- 增加未来数据、测试数据、未审核数据和越权访问测试。

验收：通过接口、后台任务或直接服务调用都无法让非生产数据进入家长预测。

### 阶段 3：定期采集与自动治理基础版（已完成基础闭环）

开发内容：

- 建立 scheduler、collector-worker 和 governance-worker；
- 支持网页、附件、文件上传和人工链接任务；
- 支持定时运行、立即运行、暂停、重试和从原始证据重新治理；
- 保存不可变快照、正文与附件哈希，完成变化检测和新旧差异；
- 结构化解析优先，大模型用于非结构化抽取和摘要；
- 完成实体匹配、字段标准化、去重、冲突识别、异常检测和候选事实生成；
- 建立逐步运行日志、告警和幂等键。

验收：官方网页、详情页、PDF 和人工表格四种样本完成“定时采集—变化检测—候选事实—失败重试”闭环；重复运行不产生重复数据。

### 阶段 4：数据工作台基础版（已完成基础闭环）

开发内容：

- 数据总览、采集任务、运行日志、变化对比、治理队列、审核发布和数据缺口页面；
- 任一发布事实可以反查原始证据、处理步骤、人工修改和发布版本；
- 冲突数据不能直接覆盖已发布数据；
- 首期录入教育局、学校官网等高优先级来源和采集计划。

验收：完整走通“任务配置—自动采集—自动治理—人工审核—发布—消费”，并能从失败日志重新执行。

完成情况：已完成任务配置、运行日志、正文与附件变化对比、治理规则版本、自动候选冲突检测、运营待办、审核发布、失败重试、数据缺口优先级、连续失败与结构异常告警、发布事实全链路追溯。分析缺少年度曲线、初中映射、班型或目标学校边界时会自动形成幂等补数任务。

## 里程碑二：核心分析模型

### 阶段 5：分析结果契约与年度分布模型（已完成基线）

开发内容：

- API 固定输出 `current_snapshot`、`reasonable_projection`、`target_comparison`、`school_tiers`、`parent_reasons` 和内部诊断；
- 保留旧接口兼容层，完成小程序平滑过渡；
- 实现 `AnnualDistributionModel` 历史曲线桥接基线；
- 输入计分方案、历年一分一段、考生人数、招生规模和政策变化；
- 输出预测年度分数—位次曲线及上下界；
- 完成跨届回测、单调性、区间覆盖和数据泄漏测试。

验收：给定历史截止时间可以复现当时预测曲线，出分后评价集不参与生成，只参与误差计算。

完成情况：已固定双情景、目标差距区间、学校梯队、结果等级和缺失输入契约；新增独立版本的年度分布模型，将历史曲线按计分满分和考生规模投影到目标年度，输出单调目标曲线与位次区间；分析运行保存年度模型版本和内部一致性诊断；已建立独立评价曲线的跨届回测、单调性和覆盖率测试。后续数据补齐后继续扩展招生规模与政策特征。

### 阶段 6：学生分数—位次联合预测（进行中）

开发内容：

- 当前现状只使用最近一次成绩和年度计分口径；
- 合理预测使用成绩与排名历史、初中、班型、考试阶段、波动、难度和距中考时间；
- 建立同校同班型到地区先验的分层回退；
- 输出联合分数区间与位次区间并执行一致性校验；
- 实现完整预测、基础预测和暂不预测三级结果；
- 建立消融测试：成绩通道、排名通道、融合、趋势、难度和时间约束。

验收：分数区间映射出的位次与输出位次一致；距中考 3 天的允许变化小于距中考 3 个月；缺少关键数据时正确降级。

当前完成：当前现状保持最近一次成绩口径；合理预测已将成绩趋势位置和年级排名位置融合后，经目标年度曲线反向生成匹配的分数范围与位次范围；剩余时间已约束趋势上限和区间宽度；已实现三级结果契约和相应回归测试。待继续补充班型分层回退、排名历史趋势和分段可用宽度校准。

### 阶段 7：学校录取边界模型

开发内容：

- 将历年录取分数统一换算为录取位次；
- 按学校、校区、招生代码、批次和年度保存招生观察；
- 综合近年位置、招生计划、定向名额、政策变化、补录和异常年份形成边界区间；
- 输出目标差距范围和冲刺、匹配、保底梯队；
- 数据不足时只输出学校层次。

验收：计划或政策变化能够改变边界中心或扩大区间，不能继续使用单一历史分数线。

## 里程碑三：家长产品闭环

### 阶段 8：异步分析、报告和月报

开发内容：

- 成绩保存后创建幂等分析任务，页面显示处理中、完成或失败；
- 分析结果和 HTML 报告原子发布，失败任务可重试；
- 每次成绩产生独立报告，修改成绩生成修订快照；
- 每个自然月最多生成一份月度升学报告；
- 报告只说明家长可理解的理由，不展示模型、参数和治理过程。

验收：连续录入 7 次成绩产生至少 7 份单次报告；修改不覆盖历史；有新成绩和无新成绩两种月报都符合规则。

### 阶段 9：小程序页面升级

开发内容：

- 首页固定展示目标、当前现状、合理预测、差距和下一步；
- 完整预测展示学校梯队，基础预测只展示学校层次，暂不预测引导补充信息；
- 档案增加可选班型，成绩增加必要考试元数据；
- 报告列表区分单次报告和月度报告；
- 清除所有面向家长的算法过程、产品能力和内部数据治理说明。

验收：开发者工具和手机真机完成新建档案、录入/修改成绩、查看双情景、报告历史和月报闭环。

## 里程碑四：生产验证

### 阶段 10：质量、性能与部署

开发内容：

- 单元、接口、数据边界、权限、端到端和真机测试；
- 固定历史评价集回测和分段质量监控；
- 200 并发下首页、成绩和报告列表 P95 不超过 500ms；
- 分析与报告 95% 在 30s 内完成；
- 执行数据库恢复、数据版本回滚和模型版本回滚演练；
- 在云服务器灰度部署，确认不影响现有 5005、5006 和其他服务。

验收：全部自动测试、数据泄漏测试、7 次闭环、采集闭环、回测、压测和真机测试通过后，才进入扩大内测。

## 开发优先级

必须先完成：阶段 1 至 7。它们决定数据是否可信、分数和位次是否一致，以及学校匹配是否成立。

形成可用闭环：阶段 8 至 9。此时家长才能稳定使用新的分析结果和报告。

上线保障：阶段 10。

本轮暂不开发：全网抓取、绕过平台限制的采集器、短视频自动下载、完整志愿优化器、知识点错题系统、支付和复杂营销功能。
